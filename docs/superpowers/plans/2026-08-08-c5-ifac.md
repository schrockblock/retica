## The algorithm, transcribed from source (do not work from summaries)

Two prior slices shipped defects because a reference block was summarized and behaviors fell off the end. This is the verbatim logic.

**Key derivation** (`Reticulum.py:959-973`):
```
ifac_origin      = full_hash(netname_utf8)  ‖  full_hash(netkey_utf8)   # either or both
ifac_key         = HKDF(length: 64, derive_from: full_hash(ifac_origin), salt: IFAC_SALT, context: nil)
ifac_identity    = Identity.from_bytes(ifac_key)
```
RNS's 64-byte private key is `X25519(32) ‖ Ed25519(32)`, so **the Ed25519 signing seed is the LAST 32 bytes** of `ifac_key`. (Independently confirmed in Lower-Sideband: `signingSeed = derived.suffix(32)`.)

**Outbound** (`Transport.py:1071-1101`):
```
ifac       = sign(raw)[-ifac_size:]
mask       = HKDF(length: len(raw)+ifac_size, derive_from: ifac, salt: ifac_key, context: nil)
new_header = [raw[0] | 0x80, raw[1]]
new_raw    = new_header ‖ ifac ‖ raw[2:]
masked[i]  = i == 0                       -> (new_raw[0] ^ mask[0]) | 0x80
             i == 1 or i > ifac_size+1    -> new_raw[i] ^ mask[i]
             else                         -> new_raw[i]            # the IFAC is NOT masked
```

**Inbound** (`Transport.py:1442-1476`):
```
require raw[0] & 0x80 == 0x80                      else drop
require len(raw) > 2 + ifac_size                   else drop
ifac         = raw[2 : 2+ifac_size]
mask         = HKDF(length: len(raw), derive_from: ifac, salt: ifac_key, context: nil)
unmasked[i]  = i <= 1 or i > ifac_size+1 -> raw[i] ^ mask[i]
               else                      -> raw[i]
new_header   = [unmasked[0] & 0x7f, unmasked[1]]
new_raw      = new_header ‖ unmasked[2+ifac_size:]
expected     = sign(new_raw)[-ifac_size:]
require ifac == expected                           else drop
accept new_raw
```

**A non-obvious property worth preserving deliberately.** Outbound sets bit 7 *after* masking (`| 0x80`), while inbound simply XORs it back. When `mask[0]` has bit 7 set these are not inverses — the recovered bit 7 is wrong. It does not matter, because `new_header` clears it with `& 0x7f` before the signature is computed, and outbound signed the original `raw` whose bit 7 was already clear. Do not "fix" this asymmetry; it is load-bearing for wire compatibility.

**If IFAC is not configured on an interface**, an inbound packet with the flag set is dropped (`Transport.py:1482-1486`). Conversely a configured interface drops packets without the flag.

```swift
import Foundation
import SwiftEdDSA

/// Deterministic RFC-8032 Ed25519 signing, used ONLY by IFAC.
///
/// IFAC authenticates a packet by having the receiver RE-SIGN it and byte-compare against
/// a 16-byte tail carried on the wire (RNS Transport.py:1073 vs :1469-1473). Sixteen bytes
/// is a fragment of the 64-byte signature — too short to verify — so comparison-by-
/// recomputation is the only available check, and it requires `sign(key, message)` to be a
/// pure function.
///
/// CryptoKit's `Curve25519.Signing` is HEDGED (randomized): RFC 8032 permits it and Apple
/// uses it for fault-injection resistance. Signatures stay valid but are not reproducible,
/// so a CryptoKit-based node could not verify even its own outbound IFAC. Hence this
/// separate, pinned backend. Everything else in the stack keeps using CryptoKit —
/// elsewhere signatures are VERIFIED (deterministic) or relayed verbatim, so hedging is
/// harmless there.
///
/// Do not replace this with CryptoKit. `DeterministicSignerTests` will fail if you do.
public enum DeterministicSigner {
    /// Signs `message` with a 32-byte Ed25519 seed, returning the 64-byte signature.
    /// Traps on a wrong-sized seed: every caller derives the seed via HKDF, so a bad
    /// length is a programmer error rather than a runtime condition.
    public static func sign(message: Data, seed: Data) -> Data {
        precondition(seed.count == 32, "Ed25519 seed must be 32 bytes, got \(seed.count)")
        let key = try! PrivateKey(s: [UInt8](seed))
        return Data(try! key.sign(message: [UInt8](message)))
    }
}
```
