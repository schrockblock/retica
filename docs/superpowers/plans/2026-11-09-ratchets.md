# Ratchets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Match RNS 1.6.0 / LXMF 1.3.0 ratchets: peers' ratchets are kept per destination and used for every encryption to them (propagated LXMF included), and ReTiCAMsgr announces its own rotating ratchets and decrypts with them, so a peer that enforces ratchets can exchange messages with us and messages to us get forward secrecy.

**Architecture:** Peer ratchets move from the path entry (`LearnedDestination.ratchet`) to `KnownDestination`, refreshed by every valid announce and expired at 30 days, as reference's `known_ratchets`. Own ratchets are a per-destination ring of X25519 private keys in Transport state, rotated at announce time; the host persists the ring (private keys, so the app uses the Keychain) and must restore it before enabling — the library makes ratchets an explicit host opt-in that takes the restored ring.

**Tech Stack:** Swift 6, TCA, Swift Testing; reference RNS 1.6.0 / LXMF 1.3.0 in `/Users/ell/opt/anaconda3/envs/rns-latest`.

**Spec:** `docs/superpowers/research/2026-11-08-lxmf-1.3-parity.md` §2 (reference with file:line; ReTiCA today; gap list 1-8) and the reference source.

## Global Constraints

- Same rules as the SDD workspace's `constraints.md`.
- Wire and lifecycle values verbatim from reference: ratchet key 32 bytes (X25519), `RATCHET_COUNT = 512`, `RATCHET_INTERVAL = 30 min` (rotate only at announce time), `RATCHET_EXPIRY = 30 days` for peers' ratchets, ratchet id = `full_hash(pub)[:10]`, announce carries `pub(ring[0])` after the random hash with `context_flag` set and signed over.
- Deliberate divergence (Ruling): reference enables ratchets on every LXMF delivery destination by default. ReTiCA enables them only when the host passes a restored (possibly empty) ring with `.enableRatchets`; README says why — a ring lost on relaunch makes every message encrypted to an old ratchet undecryptable, including ones a propagation node holds for days.
- Live interop is required: a reference LXMF 1.3.0 peer with `enforce_ratchets=True` must receive our opportunistic and propagated messages, and we must decrypt messages it encrypts to our ratchet — as `LiveStampInteropTests` does it (assert on the peer's log).

## Review Focus

1. A ratchet-less announce must not clear a known peer ratchet; a fresher announce that loses the path decision must still refresh it.
2. Rotation happens only when announcing and at most every 30 minutes; the first announce after enabling rotates (reference: `latest_ratchet_time` starts at 0).
3. A message encrypted to any of our 512 retained ratchets decrypts; one encrypted to the identity key decrypts unless `enforceRatchets`; with enforcement it is dropped.
4. Announce app-data budget shrinks by 32 bytes when ratchets are enabled, and stale captured app data is re-validated (the warning at `LXMFAnnounceData.swift:80-94`).
5. A corrupted or wrong-length restored ring entry is dropped, never trapped on, never announced.

### Deferred follow-ups
- **Inbound decrypt cost with our own ratchets** (Task 2 review I1). With a full ring, each SINGLE
  packet to an enabled destination that no ratchet opens costs up to 513 X25519 agreements (about
  15-20 ms on a Mac; unmeasured on a phone). That covers junk and every packet to the identity key,
  and it runs in Transport's reducer, on the main actor in a TCA host. No inbound rate bound covers
  DATA. This is parity with reference, which is worse on failure. It is documented at the decrypt
  site in Transport.swift and in the README.
  - Candidate fixes: an inbound SINGLE-decrypt budget per interface, or moving the decrypt off the
    main actor.
  - Not built in Task 2.
  - Closed 2026-11-10 by the parity follow-ups plan, Task 2 (`2026-11-10-parity-followups.md`): a
    shallow scan of the 16 newest ratchets plus the identity key, then a deep scan only with a
    per-interface budget. The 513-agreement figure now applies to at most 8 packets per burst and
    1 per second per interface.
