# LXMF stamp tickets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ReTiCA uses, validates and (optionally) issues LXMF 1.3.0 stamp tickets, and ReTiCAMsgr remembers the tickets peers give it across launches, so messages to a peer that gave us a ticket need no proof-of-work.

**Architecture:** Ticket state lives in `LXMFNode.State` (outbound tickets we may use, inbound tickets we issued, last ticket delivery per peer). Persistence is the host's job, as for learned peers: the node reports changes as delegate actions and restores them with one rehydrate action. Expiry is checked where a ticket is used and on rehydrate; no timer.

**Tech Stack:** Swift 6, TCA, Swift Testing; reference LXMF 1.3.0 at `/Users/ell/opt/anaconda3/envs/rns-latest/lib/python3.12/site-packages/LXMF`.

**Spec:** `docs/superpowers/research/2026-11-08-lxmf-1.3-parity.md` §1 (reference behaviour with file:line, ReTiCA's gap list), and the reference source as the authority.

## Global Constraints

- Same rules as the SDD workspace's `constraints.md` (shell, trailers, three-step verification, full suite, app worktree rules).
- Wire values verbatim from reference: `FIELD_TICKET = 0x0C`; ticket 16 bytes; `[expires (float), ticket]`; ticket stamp `truncated_hash(ticket + message_id)` (16 bytes); `COST_TICKET = 256`; `TICKET_EXPIRY = 21 d`, `TICKET_GRACE = 5 d`, `TICKET_RENEW = 14 d`, `TICKET_INTERVAL = 1 d`.
- Cross-validate against reference: a ticket stamp ReTiCA makes validates in reference, and one reference makes validates in ReTiCA (fixture generated by a committed Python script, as the repo's other `generate_*_fixtures.py` do).
- Issuing is OFF by default (reference leaves `include_ticket` to the client). ReTiCAMsgr does not issue: it advertises no stamp cost of its own, so peers have nothing to save.

## Review Focus

1. A ticket from an unvalidated message (unknown sender identity, so `signatureValidated == false`) must never be remembered — anyone could plant one.
2. A hostile `FIELD_TICKET` (wrong length, non-numeric / NaN / infinite expiry, wrong container) is ignored without trapping.
3. An expired outbound ticket is never used; the send falls back to the normal cost wait / proof-of-work path.
4. A send with a usable ticket must not wait for the peer's cost (first-send wait) and must not start a search; it must not report a Preparing phase.
5. A ticket-stamped inbound message validates only against tickets WE issued TO that sender, not tickets issued to someone else.

### Task 1: Use and validate tickets (ReTiCA library)

**Files:** `Sources/ReTiCA/LXMF/LXMessage.swift` (constants, ticket stamp, `validateStamp(targetCost:tickets:)`); `Sources/ReTiCANode/LXMFNode.swift` (state, inbound remember, outbound use in `deliverySend`, `sendViaPropagation` and the fallback propagated copy, inbound validation); a fixture generator + JSON under `Tests/ReTiCATests/Vectors/`; tests.

**Interfaces — Produces:**
```swift
// LXMessage
public static let fieldTicket: Int = 0x0C
public static func ticketStamp(ticket: Data, messageHash: Data) -> Data   // 16 bytes
public func validateStamp(targetCost: Int, tickets: [Data]) -> Bool       // tickets first, then PoW
// LXMFNode.State
public var outboundTickets: [Data: LXMFNode.Ticket]      // peer delivery hash -> ticket we may use
public var inboundTickets: [Data: [LXMFNode.Ticket]]     // peer delivery hash -> tickets we issued to it
public struct Ticket: Equatable, Sendable { public var ticket: Data; public var expires: Date }
// LXMFNode.Action.Delegate
case ticketReceived(destinationHash: Data, ticket: LXMFNode.Ticket)
```
- [ ] Remember: a `messageReceived` whose signature validated and whose fields carry a well-formed unexpired `FIELD_TICKET` upserts `outboundTickets[sourceHash]` (newest wins) and reports `.ticketReceived`.
- [ ] Use: when an unexpired outbound ticket exists for the destination, the delivery copy gets the ticket stamp with no wait and no search (even when the peer advertises no cost, as reference), and so does a propagated copy's delivery stamp.
- [ ] Validate: inbound validation (only when we have a cost) checks unexpired `inboundTickets[sourceHash]` first; a match is valid. Narrow the "unticketed" divergence comments.
