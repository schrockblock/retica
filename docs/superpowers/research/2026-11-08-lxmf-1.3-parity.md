## 1. LXMF stamp TICKETS

### (a) Reference (LXMF 1.3.0)

Constants — `SP/LXMF/LXMessage.py:42-53`
- `TICKET_LENGTH = TRUNCATED_HASHLENGTH//8` = 16 bytes
- `TICKET_EXPIRY = 21 days`, `TICKET_GRACE = 5 days`, `TICKET_RENEW = 14 days`, `TICKET_INTERVAL = 1 day`
- `COST_TICKET = 0x100` (256: the "stamp value" reported for a ticket-derived stamp)
- `FIELD_TICKET = 0x0C` — `SP/LXMF/LXMF.py:19`

Wire format: `fields[0x0C] = [expires, ticket]` where `expires` is a Python float (unix time, `now+expiry`)
and `ticket` is 16 random bytes (`LXMRouter.py:1224-1228`). It is inside the signed/hashed payload, so it
must be set BEFORE pack (`handle_outbound` sets it at `LXMRouter.py:2098-2100`, pack at :2102).

Ticket-derived stamp: `stamp = RNS.Identity.truncated_hash(ticket + message_id)` — 16 bytes, not 32
(`LXMessage.py:306-310`). Carried in the normal payload[4] stamp slot.

Generating/sending (receiver side issues tickets to people it talks to):
- Opt-in per message: `LXMessage(..., include_ticket=False)` (`LXMessage.py:114,166`). Nothing in the router
  sets it; the client app decides (whether MeshChatX does is UNVERIFIED).
- `generate_ticket(destination_hash)` `LXMRouter.py:1205-1228` (store) / `:1230-1257` (legacy):
  1. if a ticket was DELIVERED to this dest less than `TICKET_INTERVAL` (1 day) ago → return None (don't include one);
  2. else reuse an existing inbound ticket for that dest with more than `TICKET_RENEW` (14 d) validity left
     (`Storage.py:266-277`: `ORDER BY expires DESC LIMIT 1` where `expires > now+renew`);
  3. else mint `os.urandom(16)`, expiry `now+21d`, store as INBOUND ticket for that dest.
- On DELIVERED (`process_outbound`, `LXMRouter.py:3060-3067`): if the message had `include_ticket` and
  carried `FIELD_TICKET`, record `last_ticket_delivery[dest] = now`.

Receiving/remembering (sender side learns tickets it may use):
- `lxmf_delivery` `LXMRouter.py:2176-2188`: only if `message.signature_validated`; entry must be a list of
  len>1, `time.time() < expires`, ticket is bytes of len 16 → `remember_ticket(message.source_hash, entry)`
  = upsert, one outbound ticket per destination, newest wins (`Storage.py:228-238`; legacy `:1266-1267`).

Using an outbound ticket:
- `handle_outbound` `LXMRouter.py:2089-2094`: `lxmessage.outbound_ticket = get_outbound_ticket(dest)`
  (unexpired only, `Storage.py:240-251`); if present and stamp was to be deferred, `defer_stamp = False`
  → stamp generated synchronously in pack (cheap), message skips the deferred-stamp queue.
- `get_stamp` `LXMessage.py:303-310`: ticket takes precedence over PoW AND over "no cost" — if a valid
  16-byte outbound ticket exists, a ticket stamp is attached even when stamp_cost is None.
- UI: `get_outbound_lxm_stamp_cost` returns None for ticketed messages (`LXMRouter.py:2136-2148`).

Validating inbound:
- `lxmf_delivery` `LXMRouter.py:2190-2198`: only when our delivery dest has a `stamp_cost`.
  `tickets = get_inbound_tickets(message.source_hash)` = unexpired tickets WE issued TO that source
  (`Storage.py:290-301`, `expires > now`; no grace at validation time).
- `validate_stamp(target_cost, tickets)` `LXMessage.py:280-301`: first, for each ticket, if
  `stamp == truncated_hash(ticket+message_id)` → valid, `stamp_value = 256`, no workblock computed; else PoW check.
- Invalid → dropped only if `_enforce_stamps` (`:2200-2208`).

Expiry / cleanup:
- `clean_available_tickets` `LXMRouter.py:1498-1540`: outbound culled at `expires < now`; inbound culled at
  `expires < now - TICKET_GRACE` (5 d). Runs at startup (`:295`) and every `JOB_STAMPCOST_INTERVAL`=120 job
  ticks × `PROCESSING_INTERVAL` 4 s ≈ 8 min (`:972, :1010-1014, :1026`).

Persistence:
- 1.3.0 primary: SQLite `storagepath/lxmf/state.db` (`LXMRouter.py:155`), tables (`Storage.py:73-90`):
  `tickets_outbound(destination_hash PK, expires, ticket)`, `tickets_inbound(ticket PK, destination_hash, expires)`
  (+ index on destination_hash), `ticket_deliveries(destination_hash PK, timestamp)`.
- Legacy/fallback msgpack file `storagepath/lxmf/available_tickets`:
  `{"outbound": {dest: [expires, ticket]}, "inbound": {dest: {ticket: [expires]}}, "last_deliveries": {dest: ts}}`
  (`LXMRouter.py:203, 352-371, 1542-1557`); imported into the store once (`:289`, `Storage.py:442-493`).

### (b) ReTiCA today

- No ticket support anywhere. The only LXMF mentions are divergence notes:
  `Sources/ReTiCANode/LXMFNode.swift:149-154` (doc on `enforceDeliveryStamps`: "Tier 3, unticketed in ReTiCA")
  and `Sources/ReTiCANode/LXMFNode.swift:991-994` (inbound validation comment). (Other "ticket" hits are the
  unrelated FCBDriverAdapter start/stop tickets.)
- Inbound validation is PoW-only: `LXMessage.validateStamp(targetCost:)` `Sources/ReTiCA/LXMF/LXMessage.swift:166-170`,
  called from `LXMFNode.swift:1003-1010`.
- Unpack accepts a bin stamp of any length (`LXMessage.swift:214-218`), so a 16-byte ticket stamp parses (and then
  fails PoW). An inbound `FIELD_TICKET` survives as a generic int-keyed field (`fields: [IntPair]`) and is ignored.
- No FIELD_TICKET constant, no outbound/inbound ticket tables, no persistence.

### (c) Gap

1. `FIELD_TICKET = 0x0C`, `TICKET_*` constants, `COST_TICKET = 256`.
2. State: `outboundTickets[dest] = (expires, ticket)`, `inboundTickets[dest] = [(ticket, expires)]`,
   `lastTicketDelivery[dest]`. Host rehydrate actions + app GRDB tables (mirror the 3 reference tables).
3. Inbound remember: on a signature-validated message (ReTiCA: source identity known) with a well-formed,
   unexpired `[expires, 16-byte ticket]` → upsert outbound ticket for `message.sourceHash`. Hostile-input
   checks: expires must be a number (float or int), finite; ticket exactly 16 bytes.
4. Outbound use: before the PoW path in `deliverySend` (and before `waitForPeerCost` — a ticket means no
   wait is needed) and in the propagated-copy path (`LXMFNode.swift:674-680`, `:1318-1331`), stamp =
   `Crypto.truncatedHash(ticket + message.hash)`; no search, no inFlightDeliveryStamps entry. Note reference
   attaches a ticket stamp even when the peer advertises no cost.
5. Issue: an `includeTicket` option on send; `generateTicket(dest)` with the 1-day interval / 14-day renew /
   21-day expiry logic; must run before the message is created/hashed (the field is in the hash).
6. On delivery-proof of a message that carried FIELD_TICKET → `lastTicketDelivery[dest] = now`.
7. Inbound validation: when `deliveryStampCost != nil`, check unexpired tickets issued to `sourceHash` FIRST
   (cheap compare; skips the ~60 ms workblock), report value 256 / valid.
8. Cleanup sweep (startup + periodic): outbound at expiry, inbound at expiry + 5 d.
9. Remove/narrow the "unticketed" divergence comments once landed.

### (d) Interop risk if left undone

- Correctness risk is LOW: a peer can only hold a ticket for us if we issued one, so with no issuing there is no
  ticket-stamped message we would wrongly reject (the LXMFNode.swift:149-154 note is right that it is harmless
  until we issue). Exception: an identity imported from a reference client that had issued tickets.
- Cost/battery: without honoring received tickets, every message to a stamp-enforcing peer pays PoW. At
  MeshChatX's cost 8 that is small (dominated by the 3000-round workblock), so tickets are an optimisation
  here, but at higher peer costs (up to ReTiCA's cap 20) it is minutes per message.
- If ReTiCA ever ENABLES `enforceDeliveryStamps` and starts ISSUING tickets, it must also implement step 7 or it
  will drop every ticket-stamped reply.
- Whether MeshChatX sends `include_ticket=True` is unverified (no source locally).

## 2. RATCHETS

### (a) Reference (RNS 1.6.0, LXMF 1.3.0)

Destination side (own ratchets) — `SP/RNS/Destination.py`
- `RATCHET_COUNT = 512` retained private ratchets, `RATCHET_INTERVAL = 30*60` s min rotation (`:87-94`).
- `enable_ratchets(path)` `:575-598`: sets `latest_ratchet_time = 0`, loads/creates the file.
- File format `:233-248`: msgpack `{"signature": sign(packb(ratchets)), "ratchets": packb([priv32, ...])}`,
  newest first; signature verified on load (`:535-573`); written via tmp+rename.
- `rotate_ratchets` `:250-262`: if `now > latest_ratchet_time + ratchet_interval` → new X25519 private key
  inserted at [0], trim to 512, persist. Called ONLY from `_announce` (`:335-338`), so rotation happens at
  announce time, at most every 30 min. NB: `latest_ratchet_time` starts at 0 after every load, so the first
  announce after each process start rotates.
- Announce `:307-379`: `ratchet = X25519 pub of ratchets[0]` (32 B) inserted between random_hash and signature,
  included in signed data (`signed = hash+pub+name_hash+random_hash+ratchet+app_data`), packet
  `context_flag = FLAG_SET` when present (`:372-376`). Also `_remember_ratchet(self.hash, ratchet)` locally.
- Decrypt `:720-752`: try every retained ratchet (newest first) then, unless enforced, the identity key; on
  failure reloads the ratchet file once and retries. `enforce_ratchets()` `:600-611`: reject anything not
  decryptable by a ratchet (`Identity.py:1255-1259`). Sets `latest_ratchet_id` (16-byte id) for receivers.
- `set_retained_ratchets`, `set_ratchet_interval` `:613-637`.

Identity side (peers' ratchets) — `SP/RNS/Identity.py`
- `RATCHETSIZE = 256` bits, `RATCHET_EXPIRY = 30 days` (`:67-76`).
- Announce parse `:813-830`: context flag set → 32 bytes after random_hash are the ratchet.
- `__finalize_av` `:726`: `if r["ratchet"]: _remember_ratchet(dest, ratchet)` on EVERY valid announce,
  independent of path-table decisions. An announce WITHOUT a ratchet does not clear a known one.
- `_remember_ratchet` `:535-575`: in-memory `known_ratchets[dest]`; persisted to the known-destinations
  store (1.6.0 DB) or legacy `storagepath/ratchets/<hexhash>` msgpack `{"ratchet": pub32, "received": ts}`.
- `get_ratchet` `:618-675`: memory → DB/file; discarded if older than `RATCHET_EXPIRY`. `_clean_ratchets` and
  DB `expire_ratchets` (`:466-470`, `:578-615`) cull >30-day entries.
- `_get_ratchet_id(pub) = full_hash(pub)[:10]` (`:521-522`, NAME_HASH_LENGTH 80 bits).
- Encrypt `:1178-1208`: ephemeral X25519 against the ratchet pub if given, else identity pub; HKDF with
  identity salt/context; token = ephemeral_pub ‖ Token ciphertext.
- `Destination.encrypt` `Destination.py:694-708`: SINGLE dest ALWAYS uses `Identity.get_ratchet(self.hash)`
  if one is known — so every opportunistic packet AND every LXMF PROPAGATED/PAPER payload
  (`LXMessage.py:437-438, 456-457`, via `destination.encrypt`) goes to the peer's latest ratchet.

LXMF use
- Every delivery destination gets ratchets: `LXMRouter.register_delivery_identity` `LXMRouter.py:418-429`,
  file `storagepath/lxmf/ratchets/<dest-hex>.ratchets`; `enforce_ratchets` only if router constructed with
  `enforce_ratchets=True` (default False, `:113,179`). Propagation destination does not enable ratchets.
- `ratchet_id` is recorded on messages for display only (`LXMRouter.py:2173, 2285, 2327, 2861`).

### (b) ReTiCA today (precise)

- ANNOUNCE OUR OWN: NO. `Transport.swift:592-594` builds every announce with `ratchet: nil`; comment
  `Transport.swift:616-617`: "ReTiCA has no own-ratchet lifecycle at all". `LXMFAnnounceData.maxAppDataBytes`
  (`LXMFAnnounceData.swift:80-100`) assumes no ratchet and warns it must drop by 32 (and stale
  `localAppData` captures be cleared) when ratchets land. `Announce.buildPayload` can already carry one
  (`Sources/ReTiCA/Destination/Announce.swift:75-82`), and `Packet.announce(ratchetPresent:)` exists (`Packet.swift:141-144`).
- PARSE PEERS' RATCHETS: YES. `Announce.swift:106-150` honours the context flag, signs over the wire ratchet,
  and stores it only if it passes a trial X25519 agreement (the "ratchet usability check", `:135-150`;
  unusable → `ratchet = nil`, announce kept).
- ENCRYPT TO RECEIVED RATCHETS: ONLY for Transport-level opportunistic sends: `Transport.swift:1475`
  `entry.identity.encrypt(plaintext, ratchet: entry.ratchet)` (`Identity.swift:103-130`). Propagated LXMF
  messages are encrypted to the identity key with NO ratchet: `Sources/ReTiCA/LXMF/LXMFPropagation+Message.swift:22`.
  (Links do their own ECDH, unaffected.)
- WHERE THE RATCHET LIVES: on the PATH entry `LearnedDestination.ratchet` (`LearnedDestination.swift:8`), not
  on `KnownDestination` (`KnownDestination.swift:17-41` has no ratchet). It is updated only when an announce
  replaces the path (`Transport.swift:1002-1005, 1054-1057`, plus stranded-route adoption `:1019-1021`). So:
  (i) a fresher announce that loses `shouldReplace` (e.g. more hops) does NOT refresh the ratchet;
  (ii) a winning announce without a ratchet CLEARS it (reference keeps it); (iii) expiry follows the path
  (path expiry), not the 30-day ratchet expiry.
- DECRYPT WITH OUR RATCHETS: plumbing exists (`Identity.decrypt(_:ratchets:enforceRatchets:)`
  `Identity.swift:132-160`, `Destination.decrypt(_:ratchets:enforceRatchets:)` `Destination.swift:92-98`), but no
  caller passes ratchets: inbound data `Transport.swift:1206` `destination.decrypt(packet.payload)`; propagated
  `LXMFPropagation+Message.swift:42,47` `recipientIdentity.decrypt(...)`. Consistent with never announcing one.
- PERSIST: library leaves it to the host. The app persists `ratchetHex` with the path row
  (`ReTiCAMsgr/ReTiCAMsgrCore/Sources/ReTiCAMsgrCore/LearnedDestinationRow.swift:44-45, 87, 108-116`;
  `Database.swift:40`). No own-ratchet file, no ratchet-id tracking, no enforce option at the LXMF layer.

### (c) Gap

Own ratchets (forward secrecy for inbound, required if any peer were to want it):
1. Ratchet ring per local SINGLE destination: up to 512 X25519 privates, newest first, 30-min min rotation at
   announce time; signed persistence (host-owned; Keychain-adjacent since they are private keys).
2. Put `pub(ratchets[0])` in our announces + path responses with `contextFlag` set; the cached
   `announceCache` contextFlag logic already exists (`Transport.swift:63-68, 1160-1163`).
3. Shrink `LXMFAnnounceData.maxAppDataBytes` by 32 and clear/re-validate `localAppData` captures (per the
   existing warning at `LXMFAnnounceData.swift:85-94`).
4. Decrypt inbound SINGLE packets and propagated LXMF with the ring first, then identity key; optional
   `enforceRatchets`. Reference reloads from disk on failure (multi-process concern; N/A for us).
5. Expose `latest_ratchet_id` if the app wants to show it.
Peer ratchets (correctness of what exists):
6. Move the peer ratchet off the path entry into a destination-keyed table refreshed by EVERY valid announce
   (like `KnownDestination`), not cleared by a ratchet-less announce, expired at 30 days by its own `received` time.
7. Encrypt LXMF propagated (and any paper) payloads to the peer's ratchet (`LXMFPropagation+Message.swift:22`).
8. Persist `(ratchet, received)` separately from the path in the app.

### (d) Interop risk if left undone

- Today, with peers on defaults (enforce_ratchets=False), everything interoperates: peers encrypt to our
  identity key (we announce no ratchet) and decrypt our identity-key-encrypted PN messages.
- A peer running `LXMRouter(enforce_ratchets=True)` would DROP: every propagated message we send it (identity
  key, `LXMFPropagation+Message.swift:22`) and any opportunistic packet sent while our stored ratchet is
  missing (cleared by a ratchet-less winning announce) or older than its 512-ring. Whether MeshChatX enables
  `enforce_ratchets` is UNVERIFIED; reference default is off.
- Stale-ratchet risk is low in practice: a peer keeps 512 ratchets and rotates at most every 30 min and only
  when it announces.
- No forward secrecy for messages TO us (security gap, not an interop break).

## 3. STAMP SEARCH PRIORITY / SCHEDULING

### (a) Reference

LXMF delivery + propagation stamps (LXMF 1.3.0):
- Default `LXMessage.defer_stamp = True`, `defer_propagation_stamp = True` (`LXMessage.py:163-164`).
- `handle_outbound` `LXMRouter.py:2113-2123`: if no stamp cost → not deferred; if outbound ticket → not
  deferred (`:2092-2094`); if not deferred and not (PROPAGATED and defer_propagation_stamp) → straight to
  `pending_outbound`; else `pending_deferred_stamps[message_id] = lxm`. PROPAGATED messages are therefore
  ALWAYS deferred (propagation stamp), even with no delivery cost.
- `jobs()` spawns `process_deferred_stamps` in a new thread every job tick (`JOB_STAMPS_INTERVAL = 1`,
  `:985-986`); jobloop sleeps `PROCESSING_INTERVAL = 4` s (`:38, :1026`).
- `process_deferred_stamps` `LXMRouter.py:2944-3033`:
  - Global `stamp_gen_lock`: if held, return (`:2947`) → exactly ONE LXMF stamp search at a time, router-wide.
  - Selection: the first entry of the dict (insertion order) → FIFO by enqueue time (`:2953-2958`; the TODO
    "Improve logic and add stamp_cost_known here" admits there is no smarter ordering).
  - Per message, delivery stamp first (`get_stamp`, 3000-round workblock), then the propagation stamp
    (`get_propagation_stamp`, 1000-round workblock, cost from `get_outbound_propagation_cost`, which may block up
    to the path-request wait) (`:2979-3029`). Only after both → `pending_outbound`.
  - Cancelled (`cancel_outbound` sets state + `LXStamper.cancel_work` for message_id AND transient_id,
    `:1939-1946`) → removed, failed callback; a search returning None while not cancelled → `fail_message`.
  - No priority between delivery and propagation stamps beyond "both for message A before anything for B".
- Generation engine `SP/RNS/Stamps.py:254-283`: Darwin/Windows → single-core `job_simple`; Android → worker
  pool; Linux → `jobs = cores if cores<=12 else cores/2` processes when cost ≥ `POOLING_THRESHOLD_COST` 14
  (`:50, :273-274, :419, :495-496`), else single process. `cancel_work` `:348-387`.
  `generate_stamp` raises for cost <0 or > `STAMP_COST_CAP` 100 (`:255`) and for a duplicate in-flight
  material (`:258`).
- Peering keys (PN): per-peer lock + its own thread (`LXMPeer.py:244-263, 285-288`) — NOT behind stamp_gen_lock.
- Reference bug worth knowing: the cancel/fail branches call `self.__execute_failed_callback(lxmessage)`
  (`LXMRouter.py:2965, 2994, 3024`) with the loop variable `lxmessage` (the LAST dict entry), not
  `selected_lxm`, so the failed callback can fire for the wrong message when >1 are queued.

RNS 1.6.0 network stamps (separate from LXMF):
- One daemon `stamper_thread` (`Transport.py:1444-1493`) consuming `WorkerQueues((32, 32))` (`:99-130, :209-215`):
  queue 0 = `STAMP_PR_PRIORITY` (path requests and path-response announces), queue 1 =
  `STAMP_DST_PRIORITY` (ordinary announces). `get` always drains queue 0 first. `put` with a key removes any
  queued item with the same key (announce keyed by destination hash → newest replaces queued; PR keyed by
  dest(+interface)); full queue → item dropped.
- Path-request stamps: `PR_VALUE` 15.8, 15-s watchdog cancel, 256-entry cache by material (`:203, 206, 216-217, 4019-4049`).
- Link-request stamped keys: per-link thread with 15-s watchdog (`Link.py:335-363`), so concurrent across links.
- No coordination between the RNS stamper thread and the LXMF stamp_gen_lock: up to one network stamp + one
  LXMF stamp + N link keys + N peering keys run at once.

### (b) ReTiCA today

- Each message starts its own concurrent `.run` effect:
  - delivery: `LXMFNode.deliverySend` `LXMFNode.swift:1417-1438` (one `LXStamper.generateStamp` per message,
    cancellable by `CancelID.deliveryStampFor(hash)` and the group `CancelID.deliveryStamp`);
  - propagated: `.sendViaPropagation` path `LXMFNode.swift:674-682` and `startPropagatedCopy` `:1318-1331`
    (delivery stamp then PN stamp sequentially inside ONE effect per message — same order as reference);
  - restamps after a late cost `restampUnsentHandOvers` `:1504-1516`.
- Searches cooperate via `Task.yield()` every 32 rounds (`LXStamper.swift:94, 116-125`); no global cap, no
  queue, no ordering. `inFlightDeliveryStamps` is "oldest first" (`LXMFNode.swift:156-177`) but only for
  bookkeeping/failure reporting, not scheduling.
- Network stamps likewise per-item effects: destination stamp per hash `Transport.swift:636-642`, path-request
  stamp per destination `:1572-1604` (task group), link key per pending link `LinkPlane.swift:292-313`.
  No PR-over-announce priority, no bounded queue.

### (c) Gap

1. A single serial LXMF stamp worker: FIFO queue of (messageHash, kind ∈ {delivery, propagation}, cost,
   material); start the next only when the current finishes or is cancelled. Delivery then propagation for the
   same message, as reference.
2. Cancel semantics preserved: cancelling a queued (not yet started) item removes it; cancelling the running one
   cancels its task; `.cancelDeliveryStamps`/`.cancelPropagationStamps`/`.cancelOutbound` must cover both.
3. Distinguish "queued" vs "generating" for UI/progress (reference exposes progress via
   `get_outbound_progress`/`get_outbound_lxm_stamp_cost`).
4. Ticketed or cost-less messages bypass the queue (reference `:2092-2094, 2113-2115`).
5. Optional: a network-stamp worker with PR > announce priority and per-key dedupe/bounded queues
   (`WorkerQueues`), and a policy for how LXMF and network stamp work share CPU (reference: they run in parallel).
6. Do NOT copy the reference failed-callback bug.

### (d) Interop risk if left undone

- None on the wire: stamps are per-message and order-independent.
- Behavioural: with N queued messages ReTiCA finishes all of them around the same (late) time instead of
  delivering the oldest first; on a 2-core phone concurrent searches at high cost also compete with transport
  work (yield mitigates starvation, not throughput). At MeshChatX's cost 8 each search is short, so the
  practical impact there is small; it grows with cost (cap 20).

## 4. EXACT (FRACTIONAL) COSTS

### (a) Reference

Arithmetic — `SP/RNS/Stamps.py` (shared by LXMF via `LXStamper.py:10-13`):
- Fixed point: `COST_FP_BITS = 8`, `COST_FP = 256`, `MANTISSA_BITS = 33`, `TAB[256]` authoritative table
  (`:761-821`, with digest asserts).
- `cost_to_fp(c) = clamp(floor(c*256 + 0.5), 0, STAMP_COST_CAP*256)` (`:823-825`); `quantize_cost` (`:842-843`).
- `target_from_fp(fp)`: `i, f = divmod(256*256 - fp, 256)`; `target = (TAB[f] << i) >> 33` (`:845-857`).
  For integer c this is exactly `2^(256-c)`, i.e. identical to the legacy LXMF rule.
- `stamp_valid(stamp, cost, wb)`: `int(full_hash(wb+stamp)) <= target_from_fp(cost_to_fp(cost))` (`:191-196`).
- `stamp_value(wb, stamp)`: `((lz+1)<<8) - bisect_right(TAB, mantissa)` / 256, floored onto the 1/256 grid
  (`:104-189`).
- `generate_stamp(material, cost, expand_rounds, size)` converts to fp and searches `hash <= target` (`:254-283`).
  LXMF wrapper forces `size = 32` (`LXStamper.py:19, 23-24`); expand rounds 3000 delivery / 1000 PN / 25 peering.
- `STAMP_COST_CAP = 100` (`Transport.py:198`).

Delivery destination costs (LXMF 1.3.0):
- `set_inbound_stamp_cost` accepts int OR float; `< 1` → None; `< STAMP_COST_CAP (100)` accepted; else refused
  (`LXMRouter.py:444-462`). NOTE the cap is now 100, not the old 255.
- Emit `get_announce_app_data` `LXMRouter.py:1163-1182`: `stamp_cost = quantize_cost(cost)` if `0 < cost < 100`;
  app data = `[display_name, ceil(stamp_cost) or None, [SF_COMPRESSION], stamp_cost]` — element [3] is the

### (c) Gap

1. LXMF stamp arithmetic in fixed point: `LXStamper.stampValid/stampValue/generate*` taking `Double` cost and
   using `NetworkStamp`'s `target(fixedPoint:)`/TAB value logic over the LXMF workblocks with 32-byte stamps
   (refactor NetworkStamp's target/value/hashMeets into a shared primitive; it is currently `private`).
   Stamp values become `Double` (quantized), incl. `validatePnStamp`'s returned value and PN store.
2. `LXMFAnnounceData.stampCost` → `Double?` (quantized); parse [3] exactly instead of ceiling; emit
   `[name, ceil(cost) or nil, [0], quantized float]` (4 elements) while the transition lasts.
3. Cost gates: `0 < cost < 100` (STAMP_COST_CAP) on emit and in `setDisplayName`, accepting floats;
   reference refuses ≥100 rather than nulling.
4. `LearnedPeer.stampCost`, `State.deliveryStampCost`, `deliveryStampCost()` and the caps → Double.
5. `PNAnnounce`: Double cost/flex/peering; parse [7] exactly; emit [5] ceil + [7] exact.
6. PN serving: `minStampCost` → target cost + flexibility, validate at `max(0, cost - flex)` (Double);
   advertise real flex/peering.
7. Peering-key generate/validate at Double cost.
8. Persistence: app rows that store costs as integers need a REAL column.

### (d) Interop risk if left undone

- LOW for correctness. Ceiling a fractional cost always produces a stamp valid at the fractional target (a
  stamp with ≥ceil(c) leading zeros has hash < 2^(256-ceil c) ≤ target(c)); the price is up to ~2× expected
  work (e.g. 8.1 → 9 ≈ 1.87×). MeshChatX's default 8 is an integer, so no penalty there.
- Our emitted 3-element delivery app data and 7-element PN app data parse correctly in 1.3.0 (falls back to [1]/[5]).
- Two real edge risks: (i) after the 1.6.2 transition, reference puts the float in [1]/[5] directly — our parse
  already accepts floats there (ceil), fine; (ii) our emit gate is `< 255` but reference 1.3.0
  `generate_stamp` raises for cost > 100 (`Stamps.py:255`), so a ReTiCA user configuring 101-254 would make
  reference senders' deferred stamp generation throw (message stuck/failed) — gate should be < 100.
- As a PN, validating at exactly `minStampCost` with flex 0 is stricter than a reference node but consistent
  with what we advertise, so clients comply.

## Surprises / things to carry forward

- The `rns-latest` env is at `/Users/ell/opt/anaconda3/envs/rns-latest`, not miniforge.
- LXMF 1.3.0 moved tickets/stamp-costs/transient-id caches into SQLite `lxmf/state.db` (`LXMF/Storage.py`), with
  the old msgpack files only as legacy import/fallback.
- Reference STAMP_COST_CAP is 100 (RNS 1.6.0); LXMF's inbound-cost gate followed it (`< cap`), while ReTiCA still
  gates at 255.
- A ticket stamp is 16 bytes, not 32, and reference attaches one even when the peer advertises no cost.
- ReTiCA stores a peer's ratchet on the PATH entry; reference keeps ratchets in a separate per-destination
  table refreshed by every valid announce with a 30-day expiry. Consequences listed in §2(b).
- ReTiCA's propagated messages are encrypted to the identity key, never to the peer's ratchet (reference
  uses the ratchet) — the only place a ratchet-enforcing recipient would definitely reject us.
- Reference process_deferred_stamps passes the wrong message to the failed callback on cancel/failure
  (`LXMRouter.py:2965, 2994, 3024`).
- Reference rotates own ratchets only at announce time, and the first announce after every restart rotates
  (`latest_ratchet_time = 0` in `enable_ratchets`).
