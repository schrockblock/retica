# Reviewed fixed-width integer conversions in Sources/.
#
# Format:  <repo-relative file> | <occurrences> | <reason> | <expression>
#
# The expression comes LAST and is unrestricted, because Swift expressions contain `|`
# (`UInt8(high << 4 | low)`). The first three fields must not contain a pipe.
#
# Every conversion Scripts/check-wire-narrowing.swift finds must appear here or the
# check fails. Keying on the *expression text* rather than a line number means the
# entry survives edits elsewhere in the file; the occurrence count means a SECOND
# copy of the same expression is a new, unreviewed site and fails.
#
# A reason beginning with `OPEN` marks a site that is known-broken and not yet fixed.
# Those print on every run and are ticked off (entry deleted) by the task that fixes
# them. `--fail-on-open` turns them into errors — run that to assert the sweep is done.
#
# The human-readable record, with per-line detail this coarse format cannot carry,
# is docs/wire-narrowing-inventory.md. Read that before editing this file.
#
# "Int is 64-bit" is load-bearing in several reasons below. It is guaranteed by the
# `#if !_pointerBitWidth(_64) #error` at Sources/ReTiCA/Support/MsgPack.swift:15-17,
# which fails the BUILD on a 32-bit target. It is NOT guaranteed by Package.swift's
# `platforms:` list, which earlier revisions of this file cited: that declares minimum
# deployment VERSIONS for the platforms named, not the set of platforms that may build
# the package, so a consumer adding a watchOS target (arm64_32, 32-bit Int) would compile
# clean and arm four wire-reachable traps. Cite the assertion, not the manifest.
#
# Line positions in the reasons below are stated because a predecessor recorded a guard on
# the wrong line. They rot: verify by re-running this script with --report, which prints
# the current line of every conversion, and name the ENCLOSING FUNCTION alongside the line
# so the next drift is self-correcting.
